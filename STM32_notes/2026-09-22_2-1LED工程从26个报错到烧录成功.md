## 二、知识点展开

### 1. F7 → F8 的完整链路

```
Build(F7): .c → .o（编译）→ .axf（链接）→ 可执行文件
Load(F8):  .axf → 通过 ST-Link/SWD 烧进 Flash
```
`cannot open file project.axf` = 编译没成功（或压根没编）就想下载。
烧录成功的标志：`Erase Done → Programming Done → Verify OK → Application running`。

### 2. 容量宏：STM32F10X_MD

- C/C++ → Define 必须是 `USE_STDPERIPH_DRIVER,STM32F10X_MD`（逗号分隔无空格）
- **MD = Medium Density 中容量（Flash 64K~128K）**。F103**C8**T6 的 C8 = 64KB → MD
- 三处必须对齐：启动文件 `startup_stm32f10x_md.s` ↔ 容量宏 `STM32F10X_MD` ↔ 芯片实际型号
  （以后换 F103ZET6 大容量就要换 HD 和 startup_stm32f10x_hd.s）

### 3. 头文件依赖链（今天缺的就是最底层）

```
stm32f10x.h → core_cm3.h → stdint.h（uint32_t 定义在这）
```
- start 目录要放 **V3.5 版** 的 `stm32f10x.h` + `core_cm3.h`
  （来源：`STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\` 下的
  `DeviceSupport\ST\STM32F10x\` 和 `CoreSupport\`）
- **老库配老头文件配 AC5**，这是一套的；start 里那个 `备份_新版CMSIS头文件` 文件夹
  是新版 CMSIS，需要完整 CMSIS 树（cmsis_compiler.h 等），别单独拿来用

### 4. AC5 编译器注册（今天最深的坑）

**现象**：工程切到 AC5 后报
`CreateProcess failed: 'D:\keil\MDK\ARM\ARMCLANG\Bin\ArmCC'`——µVision 拿 AC6 的目录找 AC5 的 armcc。

**关键认知**：
- AC5 文件在 `D:\keil\MDK\ARM\Arm_Compiler_5.06u7`（bin 齐全），但 **µVision 必须通过 GUI 注册才知道它**：
  1. Project → Manage → Project Items… → Folders/Extensions 页
  2. "Use ARM Compiler" 行点「…」→ ARM Compiler Versions 对话框
  3. Add another Arm Compiler Version to List → 选 `D:\keil\MDK\ARM\Arm_Compiler_5.06u7`（选这层，不选 bin）
- **手工编辑 TOOLS.INI 加 ARMCCPATH1 没用**（实测：GUI 认这个条目，但编译不认，还是回 ARMCLANG 找）
- 注册成功后：魔法棒 → Target → ARM Compiler 下拉 → 选 `V5.06 update 7`，Build Output 第一行会显示
  `Using Compiler 'V5.06 update 7 (build 960)'`
- MDK-Lite（未激活）用 AC5 有 32KB 代码上限，点灯工程（Code=1112）远够

### 5. 头文件自包含原则（铁律）

每个 .h 必须**自己 include 它用到的所有东西**，不能赌"别人先包含了"。

```c
// Delay.h —— 正确示范
#ifndef __DELAY_H
#define __DELAY_H
#include <stdint.h>          // ← 用了 uint32_t 就自己带上
void Delay_ms(uint32_t xms);
void Delay_s(uint32_t xs);
#endif
```
之前在 main.c 里不报错，纯粹是 `stm32f10x.h` 那条链把 stdint.h 捎带进来了——
include 顺序变了就炸，而且报错在别人的 .c 里，极难查。

### 6. include 大小写 + "分组 ≠ 文件夹"

- `#include "Delay.h"` 必须跟文件名**一字不差**。Windows 不分大小写所以能编译，
  但 Keil 编辑器标红；挪到 Linux（大小写敏感）直接找不到文件
- Keil 左边工程树的 Group（分组）是**虚拟的**，只管显示；文件物理上在哪跟分组无关
- **新建文件默认存在工程根目录**！想让模块住 `system\` 或 `Hardware\`，要么建组时注意路径，
  要么事后挪文件 + 重新 Add + Include Paths 对齐
- 三者对齐：**物理位置 = 工程文件引用路径 = Include Paths**，缺一不可

### 7. 链接错误的形态

调用不存在的函数（`Delay(500)` 但只有 `Delay_ms`）：
- 编译期：AC5 只给 "implicit declaration" 警告（容易漏看）
- 链接期：`L6218E: Undefined symbol Delay` ← 这才是必炸点
**纪律**：见 warning 别无视，C 的隐式声明是历史包袱，不是帮你兜底

## 三、Delay 模块（今天写的代码）

```c
// Delay.c
#include "Delay.h"

void Delay_ms(uint32_t xms)
{
    uint32_t i;
    while (xms--)
    {
        i = 7200;
        while (i--);
    }
}

void Delay_s(uint32_t xs)
{
    while (xs--)
        Delay_ms(1000);
}
```

**7200 怎么来的**（72MHz 主频）：
- 8MHz 晶振 × PLL 9 倍频 = 72MHz → 1ms = 72,000 个时钟周期
- `while(i--);` 一圈约 10 个周期（AC5 无优化）
- 72,000 ÷ 10 = 7,200 圈 = 1ms

**三个特性记牢**：
1. 阻塞式——延时期间 CPU 干等（以后学定时器/SysTick 换精确方案）
2. 依赖优化等级——改 C/C++ → Optimization 会变不准，7200 要重标
3. 参数用 `uint32_t` 别用 int——`i--` 减穿 0 会回绕成 42 亿，看着像死循环

**工程结构现状**：Delay.c/Delay.h 在工程根目录，include 路径用 `.`；
规范做法（下次练习）：挪进 `system\` 或 `Hardware\` → Keil 重新 Add → Include Paths 改 `.\system`

## 四、今天的 main.c（PA0 闪烁，最终版）

```c
#include "stm32f10x.h"
#include "Delay.h"

int main(void)
{
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);   // ① 开 GPIOA 时钟

    GPIO_InitTypeDef GPIO_InitStructure;                    // ② 配结构体
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_0;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_SET);
    while (1)                                                // ③ 用外设
    {
        GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_RESET);   // 亮
        Delay_ms(500);
        GPIO_WriteBit(GPIOA, GPIO_Pin_0, Bit_SET);     // 灭
        Delay_ms(500);
    }
}
```

注意：这次用的是 **PA0**（外接 LED），不是板载 PC13。**初始化哪个脚，灯就必须接在哪个脚**。

## 五、ST-LINK connection error 排查卡（未完，明天继续）

症状：F7 正常（0 Error），F8 报 ST-Link 连接错误 = 电脑 ↔ ST-Link 这段断了，跟代码无关。
按命中率排查：
1. **拔插 ST-Link USB**，等 3 秒再插（解决大半）
2. **SWD 四根线重插**：SWDIO(PA13) / SWCLK(PA14) / GND / 3V3——动过面包板九成是碰松了
3. 关掉 ST-LINK Utility / CubeProgrammer；Keil 里 Ctrl+F5 退出调试态再 F8
4. 设备管理器看 "ST-Link Debug" 有无 / 黄叹号
5. 换 USB 口、换线（排除纯充电线）
验证方法：魔法棒 → Debug → Settings，右上 SW Device 框有 IDCODE = 物理层通
