## 二、库函数工程搭建流程（从零复刻）

### 1. 建目录结构

```
D:\stm32\Project_1_1\          ← 路径必须全英文！
├── start\      ← 启动文件 + system
├── Library\    ← 标准库源码
└── user\       ← 我的代码（main.c 等）
```

**start 文件夹放（5 件）**，从标准库复制：
- `startup_stm32f10x_md.s`（中容量专用，C8T6 = 64K Flash）
- `system_stm32f10x.c` / `system_stm32f10x.h`
- （头文件走 Include Path，见下）

**Library 文件夹放**，从 `STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\STM32F10x_StdPeriph_Driver` 复制：
- `src\` 全部 .c（stm32f10x_gpio.c、stm32f10x_rcc.c、misc.c 等）
- `inc\` 全部 .h

**user 文件夹放**，从 `...\Project\STM32F10x_StdPeriph_Template` 复制：
- `stm32f10x_conf.h`（库配置头）
- `stm32f10x_it.c`（中断服务函数）
- 自己写 `main.c`

### 2. Keil 里建工程

1. Project → New μVision Project → 选 `STM32F103C8`（Device 里搜 C8）
2. 三个 Group：`start`、`Library`、`user`，对应文件添加进去
   - .s 文件添加时，文件类型下拉切到 `Asm Source file (*.s*)`
3. 只加 .c 进 Group，**头文件不加**（靠 Include Path 找）

### 3. 魔法棒配置（核心三处）

**① C/C++ 选项卡 → Define：**
```
STM32F10X_MD,USE_STDPERIPH_DRIVER
```
- `STM32F10X_MD`：中容量芯片（少了它报 "Please select first the target STM32F10x device"）
- `USE_STDPERIPH_DRIVER`：用库函数（少了它 stm32f10x.h 跳过库声明，编译必炸）

**② C/C++ 选项卡 → Include Paths（顺序很重要）：**
```
D:\stm32\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\CoreSupport
D:\stm32\STM32F10x_StdPeriph_Lib_V3.5.0\Libraries\CMSIS\CM3\DeviceSupport\ST\STM32F10x
.\Library
.\user
```
前两条（老 CMSIS）必须排最前——标准库是 2011 年老代码，要配老 CMSIS 头文件。

**③ Output 选项卡**：勾 Browse Information（F12 跳转用）

### 4. 编译烧录

- Build（F7）→ 0 Error 0 Warning → Load（F8）
- 烧录成功标志：`Erase Done → Programming Done → Verify OK`

## 四、点灯代码（两版对照）

### 寄存器版（PC13，低电平点亮）
```c
#include "stm32f10x.h"
int main(void)
{
    RCC->APB2ENR |= RCC_APB2ENR_IOPCEN;   // 开 GPIOC 时钟
    GPIOC->CRH = 0x00300000;              // PC13 推挽输出（bit20~23）
    GPIOC->ODR  = 0x00000000;             // 拉低 → 灯亮
    while (1);
}
```

### 库函数版（三段式套路）
```c
#include "stm32f10x.h"
void Delay_ms(uint32_t count)
{
    uint32_t i;
    while (count--)
        for (i = 0; i < 7200; i++);       // 裸估 1ms @72MHz，不准，够用
}
int main(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);   // ① 开时钟
    GPIO_InitStructure.GPIO_Pin   = GPIO_Pin_13;            // ② 配结构体
    GPIO_InitStructure.GPIO_Mode  = GPIO_Mode_Out_PP;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOC, &GPIO_InitStructure);
    while (1)
    {
        GPIO_ResetBits(GPIOC, GPIO_Pin_13);  // ③ 用外设（BSRR，原子操作）
        Delay_ms(500);
        GPIO_SetBits(GPIOC, GPIO_Pin_13);
        Delay_ms(500);
    }
}
```

**关键认知**：CRH 从 PC8 开始、每 4 位管一个脚 → PC13 = bit20~23。
GPIO_ResetBits 内部写 BSRR 而不是 ODR——单指令原子操作，优于读改写。

## 五、今日错误清单（按时间线，每条 = 一个知识点）

### 坑 1：头文件挂进项目树 ≠ 编译器找得到
**现象**：`stm32f10x.h(486): 'core_cm3.h' file not found`
**根因**：Include Path 没配。项目树挂载只是"显示"，头文件搜索走 Include Path。
**修法**：C/C++ → Include Paths 加 `.\start`。

### 坑 2：core_cm3.h 还要拉一串同族头文件
**现象**：`core_cm3.h(63): 'cmsis_version.h' file not found`
**根因**：core_cm3.h 不是孤立的，连着 cmsis_compiler.h / cmsis_armclang.h 一串。
**修法**：Include Paths 加 CMSIS 包路径。

### 坑 3：两代 CMSIS 头文件打架（最深的坑）
**现象**：`misc.c(132): no member named 'IP' in 'NVIC_Type'`
**根因**：标准库 V3.5 是老 CMSIS 时代代码（NVIC 优先级叫 `IP`），新版 CMSIS 6 改名 `IPR`。老代码 + 新头 = 编译炸。
**修法**：Include Paths 里把 SPL 自带的老 CMSIS 两条路径排最前。

### 坑 4：#include "xxx" 优先搜"引用者所在目录"
**现象**：坑 3 修完还报错——start 文件夹里的新版 stm32f10x.h 把老 CMSIS 压住了。
**根因**：双引号 include 先搜当前文件所在目录，再走 Include Paths。system_stm32f10x.c 躺在 start 里，先撞见新版头文件。
**修法**：把 start 里的 `stm32f10x.h`、`core_cm3.h` 移进 `start\备份_新版CMSIS头文件\`。

### 坑 5：CRH 位算错——配了 PC14 不是 PC13
**现象**：灯不亮。
**根因**：`GPIOC->CRH = 0x03000000` 的 1 落在 bit24~25 = PC14。PC13 占 bit20~23。
**修法**：`0x00300000`。公式：`引脚 n → CRH 的 bit(4×(n−8))`。

### 坑 6：ST-Link 驱动没装
**现象**：Keil 报 "No ST-LINK detected"，但设备管理器里看得到它。
**根因**：Windows 识别了 USB 设备（问题代码 28 = 无驱动），Keil 层面就不认。
**修法**：用 Keil 自带驱动管理员权限安装
`D:\keil\MDK\ARM\STLink\USBDriver\stlink_dbg_winusb.inf`。

### 坑 7：八进制陷阱（灯不亮的真凶）
**现象**：驱动、烧录全通了，PC13 还是不亮。
**根因**：写了 `CRH = 00300000`——**C 语言里 0 开头的整数是八进制**！
`00300000`（八进制）= 3×8⁵ = `0x18000`，配置位全错位。编译器不报任何警告，因为八进制是完全合法的字面量。
**修法**：加 `0x` 前缀 → `0x00300000`。
**纪律**：写寄存器值永远带 `0x` 前缀。

### 坑 8：库函数写成了寄存器风格
**现象**：`RCC->APB2PeriphClockCmd(...)` 报错 / 半成品编译失败。
**根因**：库函数是独立函数不是寄存器成员，要直接调。
**修法**：`RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOC, ENABLE);`
**套路**：开时钟 → 填结构体 → GPIO_Init → Set/ResetBits。

### 坑 9：中文路径杀掉 F12 跳转
**现象**：勾了 Browse Information、Rebuild 无数次，F12 永远 "No browse info"。
**根因**：两层——
1. AC6 的浏览信息是**打开工程时后台即时生成**，不走编译期 .crf（所以 Rebuild 永远不会出 .crf 文件，Objects 里没有 .crf 是正常的）；
2. **工程路径含中文（`1-1工程文件模板`），MDK 对中文路径支持差，浏览信息静默失败**。
**修法**：工程文件夹改成纯英文名（如 `D:\stm32\Project_1_1`）。
**纪律**：**所有 Keil 工程路径全英文**——这是"编译能过但功能莫名残废"的头号惯犯。
备选：Target 选项卡把 ARM Compiler 切回 V5（AC5 走编译期 .crf，不受中文路径影响）。

## 六、杂项小知识

- **stm32f10x.h 意外改动弹窗**（"Save changes?"）→ 点**否**丢弃误敲。库的文件（start/Library）只读不写，自己的代码只住 user\。
- **左边项目树的红叉书签**：是旧报错留下的标记，编译成功不会自动清。Edit → Bookmarks → Remove All。
- **Program Size 怎么读**：Code=代码，RO-data=const/向量表，RW+ZI=RAM 占用（ZI 上电清零）。烧进 Flash 的是 Code+RO+RW。
- **读库源码是学 STM32 最快的路**：F12 跳进 `stm32f10x_rcc.c` 看 `RCC_APB2PeriphClockCmd`——就是一排 if-else 帮你写 RCC->APB2ENR。库函数没有魔法。
- **keil 里没有库函数是正常的**：标准库是 ST 单独发布的包（V3.5），谁的 Keil 都不自带。已下载放 `D:\stm32\STM32F10x_StdPeriph_Lib_V3.5.0`。
